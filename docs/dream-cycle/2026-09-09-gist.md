# host-adapters / kernel,sdk SOTA Report — 2026-09-09

TL;DR: Tonight's host-adapters rotation found the same ADR-046
unescaped-name injection class recurring in 2 more sibling adapters
(host-claude-code, host-codex — the two most prominent hosts), but rather
than shipping a 5th/6th "found another sibling" PR (rejected per STEP 1.1 —
this class has now appeared 4 times), the finding was redirected one layer
down: `writeAtomic()`, the single shared choke point every generated file
in this repo is written through, trusted `RenderedFile.path` completely and
would follow a `../`-shaped path outside its staging directory. 2026's own
CVE record (Semantic Kernel CVE-2026-25592, Langflow CVE-2026-5027, both
"unvalidated path → arbitrary file write" in an agent framework) shows this
exact bug shape is a live, currently-exploited category, not a theoretical
one. Fixed the choke point plus the 2 concrete unfixed instances in one
patch — then an independent critic caught a real 4th sub-gap (a
comment-line newline-injection variant this round's author had already
patched everywhere else) before ship, closed same-night.

## MetaHarness Current Capability

Each host-* adapter renders a `HarnessSpec` into host-native config
(YAML/TOML/shell/markdown) via its own `generateConfig()`. 10 adapters
exist; 6 have now needed the "unescaped name breaks generated structured
content" fix (hermes #188, github-actions #212, host-rvm #224,
host-openclaw #246, and tonight's host-claude-code + host-codex).
`host-prime-agent` (built later, ADR-247) already internalizes the lesson
with its own `shellQuote`/`quoted`/`normalizeSkillName` helpers, citing "the
ADR-046 bug class" explicitly in its source comments — proof the fix
pattern is known and cheap, just not shared. Every adapter's output is
eventually written to disk by `create-agent-harness`'s `writeAtomic()`
(`packages/create-agent-harness/src/writer.ts`), which — until tonight —
performed zero path-containment check on the `RenderedFile.path` values it
receives.

None of the 3 external CVEs above are in a *codegen* path exactly like
ours (they're file-transfer or config-deserialization plugins), so the
"None" that would otherwise fill this table for a direct apples-to-apples
match is explained rather than left bare: the closer parallel is
architectural — every one of them is a "framework trusts an
attacker-reachable string to name or reach a filesystem location, with no
shared containment layer" bug, which is exactly what `writeAtomic()` fixes
here before an equivalent bug becomes reachable through this repo's own
generated-file surface.

## Hypothesis

Given a `RenderedFile[]` whose `path` field is not guaranteed
attacker-free (host-adapter `generateConfig()` output is explicitly
documented — `examples/host-tour/README.md` — as intended to be wired into
the write path at some point, and even absent that, defense-in-depth for a
shared choke point is warranted),
when `writeAtomic()` validates that every resolved destination path stays
within the staging directory, and `host-claude-code`/`host-codex` escape
`name`/`command`/`url`/`env` fields before interpolating them into
generated YAML/TOML/shell,
then a `../`-shaped `RenderedFile.path` should be rejected before any file
is written, and a name containing YAML/TOML/shell-significant characters
should no longer be able to inject a second document key or execute an
arbitrary shell command when the generated file is later run,
subject to:
- ordinary/benign names must render byte-identically to before (no
  gratuitous quoting regression)
- 0 regressions in the existing `create-agent-harness`, `host-claude-code`,
  `host-codex` test suites
- the injection must be disproven with a real executed-shell-command proof,
  not just a string assertion.

### Adversarial critique (independent, fresh-context subagent)

Verdict on round 1: **ACCEPT-WITH-CAVEATS**. The critic verified the
escaping/containment logic correct against a wide adversarial input set
(hand-traced `shellQuote` round-tripping for `'`, `''`, `a'b'c`; confirmed
`tomlKey`'s bare-key regex correctly rejects `.`, which the TOML spec
excludes from bare keys; confirmed `writer.ts`'s guard can never
false-positive on a legitimate path since `dst` is always literally
`join(root, ...)`) — but found one real, missed sibling gap: in **both**
files, `mcpAddCommands()`'s fallback branch for a server with neither
`command` nor `url` still interpolated `s.name` bare into a `#`-comment
line. A name containing a newline breaks out of the comment and turns the
remainder into a live, executable shell line — the exact same
"comment-line newline injection" shape host-rvm's `commentSafe()` already
named on 2026-08-24 (#224), just in a branch this round missed. This is
the value of an independent critic: the candidate's own author had already
applied the comment-line-newline lesson from host-rvm to every *other*
branch and still missed this one.

**Round 2 (post-critique)**: added a `commentSafe()` helper (mirroring
host-rvm's) to both files, applied it to the skipped-server comment line,
and added one real bash-exec regression test per file proving a newline in
a skipped server's name can no longer produce a live, uncommented
statement. Confirmed non-vacuous: both new tests fail against the round-1
patch and pass only with the round-2 fix.

- **Final candidate (round 2, patched)**: **48/48 new/modified test
  assertions pass** across the 3 touched test files.
  `packages/create-agent-harness` full suite: **615/615 passed** (was 613

## Recommended Next Steps

1. **Extract the fix pattern into a shared, tested utility** so a 7th
   sibling instance doesn't need manual rediscovery. `host-prime-agent`
   already has working `shellQuote`/`quoted`; the natural home is either a
   new small `@metaharness/adapter-safety`-shaped package or (lower-risk,
   since `kernel-js` is a wasm/NAPI-primary package not a good place for
   plain TS string helpers) a `packages/host-adapter-shared` pure-TS
   package that all `host-*` adapters can optionally depend on. Not done
   tonight: cross-package extraction is a larger, higher-risk refactor than
   this candidate's "small, reviewable" scope, and every prior accepted fix
   in this series used the same local-helper pattern.
2. **Add a repo-wide regression sweep** — one test (in `packages/bench` or
   a new lightweight script) that calls every `host-*` adapter's
   `generateConfig()` with a fixed set of adversarial names
   (`]`/`;`/`` ` ``/newline/quote-heavy) and asserts no adapter's output
   contains an unescaped instance of the raw adversarial string in a
   structurally significant position. This would have caught tonight's
   finding (and the prior 4) in one run instead of requiring a fresh manual
   audit each rotation.
3. **Wire `generateConfig()` into the actual CLI scaffold pipeline** (or
   explicitly document that it is intentionally not yet wired) —
   `examples/host-tour/README.md` describes it as the intended runtime
   path, but no call site exists in `packages/create-agent-harness/src`
   today (only tests, READMEs, and the `host-bench` benchmark call it).
   Until it's wired, the `host-claude-code`/`host-codex` fixes are
   currently latent-but-real rather than actively-exploited-today —
   `writer.ts`'s hardening is the part with an active caller
   (`walkTemplate`), which is exactly why it was prioritized as the primary
   fix rather than the per-adapter escaping.
