# `metaharness score`'s Tool-Safety Dimension Was a Repo-Independent Constant — 2026

TL;DR: ADR-041's `metaharness score <repo>` scorecard advertises six per-repo
dimensions, but in 2026 every repo ever scored got the same two `toolSafety`
values — 90 or 100 — because the calculation read `plan.policy`, which
`recommendPlan()` hardcodes to a constant `SAFE` object regardless of the
repo, and only the remaining single `plan.mcp === 'remote'` check varied.
Fixed by reusing `genome-scorers.ts`'s already-tested, already-4-way-
differentiated `scoreMcpRisk()` instead of reinventing a coarser binary
check. Measured post-fix on real fixtures: 82 vs. 95 (was 90 vs. 100).

## MetaHarness Current Capability (before tonight)

`packages/create-agent-harness/src/repo-scorecard.ts`'s `buildRepoScorecard()`
computes `toolSafety` from `plan.policy` (the *recommended* policy for a
harness that doesn't exist yet). `recommendPlan()` in `analyze-repo.ts`
always sets `policy: SAFE`, a single hardcoded constant — never derived from
the target repo. So every one of `toolSafety`'s six `if` branches
(`defaultDeny`, `allowShell`, `allowNetwork`, `allowFileWrite`,
`requireApprovalForDangerous`, `auditLog`) evaluates identically on every
call, summing to a constant 100. The only variation came from one line,
`if (plan.mcp === 'remote') safety -= 10`, and none of the 8 archetypes in
`ARCHETYPES` ever recommend `mcp: 'off'` — so `toolSafety` could only ever be
90 or 100, for any repository, forever. Verified empirically: this
repository itself, a synthetic minimal `package.json`-only repo, and every
`repo-scorecard.test.ts` fixture all scored `toolSafety: 100` pre-fix.
Meanwhile `genome-scorers.ts::scoreMcpRisk()` (used by the sibling
`harness genome` command, same package, same `(profile, plan)` inputs)
already computes a 4-way-differentiated 0–1 risk value (`off` /
`local_default_deny` / `local_permissive` / `remote`) — `repo-scorecard.ts`
never called it.

## Hypothesis

Given two structurally different repositories (one whose best-fit archetype
is `mcp-server-harness`/remote MCP, one with no MCP signal at all), when
`metaharness score <repo>` computes the `toolSafety` dimension, then the two
repos' `toolSafety` values should differ by more than the pre-fix constant
10-point gap, subject to: (a) the default-deny policy credit — a true,
architecture-level fact (every generated harness really does scaffold
default-deny) — remains unchanged; (b) `toolSafety` stays in `[0,100]`; (c)
zero regressions in `repo-scorecard.test.ts` / `genome-scorers.test.ts`; (d)
the new test fails non-vacuously against the pre-fix code. Frozen before
implementation; not modified after evaluation began.
